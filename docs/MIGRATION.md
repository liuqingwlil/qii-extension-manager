# 扩展文件迁移（Windows）

1.4.2 更新：连接状态旁提供“立即刷新”，只重新检测本地助手，不重载页面。未连接时每 5 秒自动重试，已连接时每 30 秒核验；授权、权限变化、文件操作结束或返回页面时立即检查。检测中显示转圈状态，连接恢复后迁移按钮自动启用。

1.4.1 更新：运行新版 1.1.0 助手后，会通过浏览器资料和管理器识别文件自动查找已启用的栖管理器；唯一匹配时自动配置连接，多匹配时选择对应资料，识别不到时才手动填写 ID。网页显示检测、待授权、已连接或未连接状态；首次允许本地通信后会自动重连，不必重复点击连接按钮。助手显示配置状态与浏览器最近握手状态。旧版助手应先关闭后再运行新版。

从 1.4.0 开始提供 Windows 本地迁移助手。它会备份扩展的实际文件，包含商店安装目录及浏览器登记的本地开发目录，另保存管理器的配置与清单。ZIP 不受管理器当前搜索或分组筛选影响。

**一次还原文件不等于自动安装。** 普通 Chrome / Edge 不允许管理扩展或本地助手任意静默安装全部扩展。新电脑可以一次解包全部已备份文件，之后仍需完成浏览器要求的安装与授权；不会修改企业策略或直接篡改浏览器配置来绕过确认。

## 首次连接

1. 在原来的固定目录更新管理器，在扩展页点击“重新加载”。
2. 小窗“工具”中点击“导出扩展文件 ZIP”或“导入扩展文件 ZIP”，进入完整管理页。也可直接进入完整管理页的“偏好设置”。
3. 在“扩展文件迁移（ZIP）”中下载并运行 `QiiMigration.exe`。助手已经打包 Python 与 Tk，无需另外安装 Python。
4. 助手会自动识别并配置唯一匹配的管理器；存在多个候选时选择对应资料。识别不到时选择“手动填写扩展 ID”，填入网页展示的当前 ID。此操作将助手放到当前用户的本地应用目录，并为 Chrome / Edge 注册 `com.qii.migration` 的 Native Messaging host；只允许明确填入的管理器 ID 调用。
5. 回到管理页点击“连接本地迁移助手”，允许可选的本地通信权限。助手不需要管理员身份或企业策略。

原电脑和新电脑分别连接一次。浏览器资料或解压路径变化时管理器 ID 可能不同，应使用当前页面提供的 ID。

## 导出实际文件

导入、导出在同一区域相邻排列。连接成功后点击“导出扩展文件 ZIP”，在助手中确认浏览器资料及保存位置。默认资料不能唯一对应当前管理器及清单时，必须明确选择正确目录；支持自定义资料位置。

每个扩展保存原始文件及 `manifest.json`，保留已有公钥 `key`；迁移清单保存原 ID、版本、来源、逐文件 SHA-256、数量和大小，并附带管理器 JSON。不会凭同名跨资料混配目录。

未找到目录、文件读取失败、磁盘代码与浏览器版本不一致，以及无法完整复制的链接项目会逐项报告，不会显示完整备份成功。已卸载并删除源码的历史扩展无法从清单重新生成。请将 ZIP 保存到待备份源码目录之外。

文件包保存上限为 100000 个文件、2 GiB，迁移索引上限 4 MiB，以先达到的限制为准。备份仅包含扩展代码和管理配置，不包含整个浏览器用户资料、其他扩展的私有存储、Cookie、密码或登录状态。

## 在新电脑恢复

1. 在新电脑安装本管理器并连接助手。
2. 点击相邻的“导入扩展文件 ZIP”，选择 ZIP 和保存目录。
3. 助手先校验清单、每个文件的大小和 SHA-256，再在所选位置创建新的 `Qii-Restore-...` 目录，一次恢复全部文件，不覆盖现有浏览器资料。
4. 查看恢复报告和生成的“安装扩展清单.html”。结果会明确显示“文件已还原，等待安装确认”，不会标为扩展已安装。
5. 商店扩展可从清单中的官方商店入口安装；本地扩展在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，再加载相应扩展目录。一个扩展对应一个目录，不能用总目录代替所有项目。
6. 完成浏览器安装后，回到管理器点击“预览管理配置与已安装扩展的启停恢复”，查看差异，再确认应用。

本地扩展未设置固定 `manifest.key` 时，更换目录或电脑可能改变 ID。管理器不会仅凭同名声称是相同扩展。需要原扩展额外依赖的本机程序、账号、授权或服务时，应按原扩展要求配置；备份文件不能补足这些外部依赖。

## JSON 与 ZIP 的区别

- “导出配置与清单 JSON / 导入 JSON 并应用”：配置、清单与已安装项目的启停状态，不包含扩展文件。
- “导出扩展文件 ZIP / 导入扩展文件 ZIP”：通过 Windows 助手打包及解包真实代码目录，带文件校验及管理配置。
- 旧版“导出配置 / 导入配置”继续兼容只合并配置的工作流。

## 构建和验证

助手源码、构建说明及测试位于 `tools/migration-helper`。文件测试只使用临时合成资料，不读取测试机器真实浏览器资料。界面测试的 Native Messaging 响应为隔离渲染器模拟，不能据此宣称已在用户电脑注册或完成原生通信。

官方能力依据：[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)、[Chrome 安装规则](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)、[本地扩展加载](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)、[manifest.key](https://developer.chrome.com/docs/extensions/reference/manifest/key)。
