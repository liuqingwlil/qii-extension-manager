1.3.2 修复原生小窗自动尺寸回归：`body` 提供不依赖视口的 600×590 固有尺寸，`#root` 与小窗内容继续适应浏览器实际给出的可用空间。浏览器限制窗口时，外层请求尺寸可大于视口；窄窗检查改为直接验证内容根节点、页头、列表、页脚及操作控件均在视口内，列表没有横向溢出，外层不出现滚动条。不能把外层再次改回 `100vw / 100vh`，否则会失去撑开原生窗口的固有尺寸。

原生 action 检查现在必须成功打开，不再把测量失败记为跳过；森林与爱莉希雅皮肤分别核对常规环境下至少 580×560 的可用尺寸，以及搜索、首卡、图标、名称、开关和关闭入口的实际绘制边界。之前 Chromium 无头环境已返回 600×590，因此本轮不宣称在该环境复现了用户 Edge 的几十像素塌缩。实际 Edge 窗口的 Windows 自动检查因工具无法确认当前页面地址而停止，没有继续发送界面输入。

本轮原生两种皮肤均实测 600×590。另在普通扩展测试页把初始视口设为 48×50，验证 `body` 仍提供 600×590 请求尺寸，而 `#root` 与内容为 48×50，避免再次出现尺寸链全部依赖小视口的回归。原生 action 未向 Playwright 暴露截图 Target，故没有将普通标签页截图标记为原生截图。

## 验证范围

Chrome 与 Edge 的兼容实现依据官方 Chromium 扩展 API，两个品牌浏览器没有在用户资料中手动安装验证。新增测试通过 `chrome.action.openPopup()` 打开真正的 action view，并通过 `chrome.extension.getViews({type:'popup'})` 确认其尺寸为 600×590，验证关闭按钮及 Esc 事件处理使该原生 view 关闭。丰富交互则以相同的真实扩展 `popup.html` 页面测试。

操作系统层面的鼠标失焦关闭在无头环境中无法重现；产品沿用浏览器原生失焦关闭行为，没有额外添加容易影响文件选择或授权弹窗的 `blur` 关闭监听。原生卸载确认、权限增加后的重新授权窗口，以及企业策略管理环境，仍需相应环境中的人工验收。

安装包是可“加载已解压扩展”的 ZIP，没有签名、上架商店或静默安装逻辑。组织策略限制、其他扩展的站点访问及无痕权限不能由此扩展绕过。
